# TooruDragon Architecture — v0.1.0 Alpha

## 1. Общая схема

```text
               Mobile App
                   |
                Web App
                   |
              API Gateway
                   |
               Main Core
        ___________|____________
       |           |       |     |
   Tooru/AI    Workshop   Home  Work
       |           |       |     |
       +-----------+-------+-----+
                   |
               Data Layer
```

Main Core управляет жизненным циклом системы и маршрутизацией. Специализированные ядра запускаются независимо, но работают через общий контракт.

## 2. Ядра

### Main Core
- bootstrap;
- health-check;
- service registry;
- маршрутизация;
- конфигурация;
- управление обновлениями;
- логирование;
- общая авторизация;
- API для клиентов.

### Tooru/AI Core
- AI runtime;
- диалоговый движок;
- модельный слой;
- контекст;
- память;
- инструменты;
- AI orchestration.

### Workshop Core
- code generation;
- code editing;
- testing;
- build automation;
- sandbox tools;
- developer workflows.

### Home Core
- домашние задачи;
- локальные устройства;
- автоматизация;
- расписания;
- персональные сценарии.

### Work Core
- рабочие проекты;
- задачи;
- документы;
- рабочие интеграции;
- отчёты и автоматизация.

## 3. Клиенты

### Desktop
Windows запускает локальную систему через `StartTooruDragon.bat`.

### Web
Web UI общается с API Gateway/Main Core и не зависит напрямую от реализации отдельных ядер.

### Mobile
Мобильное приложение — общий клиент для всех ядер через единый API.

## 4. Обновление

Перед локальным запуском стартовый скрипт проверяет:
`https://github.com/Aspksa/TooruDragon`

Alpha-схема:
1. проверить наличие Git;
2. получить изменения;
3. выполнить fast-forward update;
4. запустить bootstrap;
5. bootstrap поднимает ядра.

Позже обновление следует вынести в отдельный Update Service с rollback.

## 5. Данные

Предлагаемая структура:
- System DB — конфигурация, состояния сервисов, версии;
- AI DB — память и AI-контекст;
- Workshop DB — проекты, сборки, артефакты;
- Home DB — домашние сущности и автоматизации;
- Work DB — рабочие сущности;
- Shared Storage — файлы и общие объекты.

Для Alpha локально можно использовать SQLite. Для серверной/Web-версии позднее — PostgreSQL.

## 6. Базовые правила

- каждое ядро имеет собственный API;
- Main Core не хранит бизнес-логику специализированных ядер;
- клиенты работают через Main Core/API Gateway;
- ядра имеют health endpoint;
- секреты не хранятся в Git;
- обновление в дальнейшем поддерживает rollback.
