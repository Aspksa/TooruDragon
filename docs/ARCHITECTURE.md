# Архитектура TooruDragon — v0.1.0 Alpha

## Главное правило

Системные функции реализуются один раз в `core/system/`.
Ядра не копируют базу данных, авторизацию, API runtime, обновление, логи или загрузку конфигурации.

## Независимое версионирование

Проект имеет системную версию, а каждое ядро — собственную компонентную версию.

Текущий реестр:

| Ядро | Порт | Версия |
|---|---:|---|
| Main | 8700 | 0.1.0 |
| Tooru/AI | 8701 | 0.1.0 |
| Laboratory | 8702 | 0.1.0 |
| Home | 8703 | 0.1.0 |
| Work | 8704 | 0.1.0 |
| Mobile | 8705 | 0.1.0 |

Версии хранятся в `config/cores.json` и автоматически публикуются через `/health` и `/system`.

Это позволяет:
- обновлять одно ядро независимо;
- видеть несовместимые версии;
- вводить миграции по компонентам;
- делать точечный rollback;
- автоматически проверять совместимость.

## System Layer

### `core/system/config.py`
Загружает системную конфигурацию и реестр ядер, включая порт, имя и версию каждого компонента.

### `core/system/database.py`
Единый доступ к SQLite, инициализация схемы, query/execute и управление соединениями.

### `core/system/auth.py`
Общая Bearer-авторизация.

### `core/system/server.py`
Общий HTTP/API runtime: GET/POST, JSON, CORS, public/protected routes и единая обработка ошибок.

### `core/system/logging.py`
Единое логирование с ротацией.

### `core/system/updater.py`
Единый механизм обновления Git.

### `core/system/runtime.py`
Связывает конфигурацию, версию конкретного ядра, БД, авторизацию, логи и API.

## Правило дальнейшей разработки

Новая системная возможность сначала добавляется в `core/system/`.
В конкретное ядро код добавляется только тогда, когда он относится исключительно к его предметной области.


## Event Bus

Центральная шина событий работает в Main Core.

Основные точки:
- `POST /events/publish` — публикация события;
- `GET /events` — последние события;
- `runtime.events.publish(topic, source, payload)` — общий клиент для любого ядра.

Примеры тем:
- `home.device.changed`;
- `work.task.created`;
- `ai.response.ready`;
- `system.core.failed`.

## Watchdog

`core/system/watchdog.py` контролирует специализированные ядра через `/health`.

Параметры задаются в `config/system.json`:
- интервал проверки;
- число допустимых последовательных сбоев;
- автоматический перезапуск.

На Windows Watchdog может автоматически перезапустить упавшее ядро через его `start.bat`.

## Compatibility Manager

`core/system/compatibility.py` проверяет зависимости версий по `config/compatibility.json`.

Main Core публикует результат через:
- `GET /compatibility`.

Это защищает систему от запуска заведомо несовместимого набора компонентов.
