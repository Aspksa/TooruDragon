# Document Intelligence — TooruDragon

## Назначение

Documents Tooru — единый канонический контур рабочих документов. Он заменяет
разрозненный пользовательский RAG-ввод и объединяет оригинал файла, извлечённый
текст, тип документа, Паспорт, ДНК, факты с provenance, версии, связи,
проверки, RAG-индекс и журнал загрузок.

RAG остаётся внутренним поисковым слоем. Пользователь работает с документом,
а не с отдельной сущностью RAG document.

## Конвейер

    file/text
      -> extract
      -> classify
      -> deduplicate
      -> resolve family/version
      -> extract facts + provenance
      -> build Passport
      -> build DNA
      -> run document rules
      -> build relations
      -> cross-document checks
      -> set studied/attention/error
      -> index in RAG
      -> publish work.document.* event

## Паспорт документа

Паспорт содержит document_id, family_id, version, title/original_name,
type/type_label, number/date/year, logical archive_path, status, content SHA-256,
количество извлечённых фактов и состояние сохранения оригинала.

Паспорт не является отдельным источником истины. Он формируется из канонической
записи документа и фактов.

## ДНК документа

ДНК содержит content_sha256, normalized_sha256, structure_sha256,
fact_fingerprint, структурные счётчики, даты, номера документов,
идентификаторы техники, ссылки и длину текста.

ДНК используется для дедупликации, поиска версий, диагностики и будущего
сравнения документов.

## Типы документов

Поддерживаются service_memo, contract, invoice_offer, invoice, act, order,
timesheet, vehicle_document и other.

Классификация в первую очередь использует название и заголовок документа,
чтобы упоминание договора внутри счёта не превращало счёт в договор.

## Правила проекта

Служебные записки обрабатываются специальным правилом только для этого типа.
Логическая папка: Служебные записки/<год>. Если год не определён, создаётся
проблема service_memo_year_unknown.

По правилу проекта счёт-оферта предназначен для товара. Если в нём найдены
признаки услуг/работ, создаётся ошибка invoice_offer_contains_services.

Запчасти и услуги не привязываются к гаражу без явного идентификатора.
Документы связываются по подтверждаемым идентификаторам, например госномеру
или VIN.

## Provenance

Каждый автоматически извлечённый факт хранит тип и ключ, исходное значение,
нормализованное значение, confidence, char_start/char_end, excerpt из
оригинального текста и verified flag.

## Автоматические проверки

Текущие проверки включают неизвестный тип, отсутствие номера/даты,
несоответствие года имени файла и текста, счёт-оферту с признаками услуг,
изменение ключевых реквизитов новой версии, один госномер с разными VIN,
документ раньше связанного договора, несовпадение явно указанных контрагентов
и ошибки сохранения оригинального файла.

## Версии и дубликаты

Точный SHA-256-дубликат не создаётся второй раз.

Документы одного типа и номера объединяются в family:

    family_id
      v1
      v2 -> supersedes v1
      v3 -> supersedes v2

Новая версия сравнивается с предыдущей по ключевым реквизитам.

## Оригиналы файлов

Файлы сохраняются рядом с базой данных:

    documents/<archive_path>/<family_id>/v<version>/<filename>

Архивирование документа не удаляет оригинал.

## Архив вместо hard delete

Маршрут /documents/archive помечает документ archived, исключает его из
активного списка и AI RAG-индекса, но сохраняет карточку, факты, связи,
историю и оригинал.

Hard delete намеренно не используется в пользовательском workflow, чтобы не
терять доказательную и версионную историю.

## Файловые адаптеры

Встроенно поддерживаются TXT, MD, CSV, JSON, LOG, DOCX и XLSX.
Для PDF используется pypdf, если он установлен. Scanned PDF без текстового
слоя требует отдельного OCR-контура.

Legacy DOC не разбирается молча: возвращается явная диагностическая ошибка и
не создаётся ложная карточка изученного документа.

## Диагностика

work_document_ingest_log сохраняет filename, source, status
(studied/duplicate/failed), document_id, error_type, message и timestamp.
Эти данные входят в machine-readable system report.

## UI

Пользовательский центр — Документы Тоору. Agent Console больше не содержит
отдельную RAG-форму. Чат продолжает использовать RAG автоматически через
ChatRuntime.

## Следующие расширения

Архитектура подготовлена для OCR scanned PDF/images, детального извлечения
таблиц и позиций, графа people ↔ vehicles ↔ documents ↔ companies ↔ parts ↔
work ↔ money, сверки цен и количества invoice ↔ contract, supplier master-data,
AI-assisted extraction с deterministic verification, filesystem watcher и
проактивных SLA-alerts.
