# Гараж · ГСМ — TooruDragon

## Назначение

Модуль связывает справочник сотрудников, топливные карты, автомобили, путевые
листы и ежемесячные выписки ГСМ.

Основная цепочка:

    топливная карта -> сотрудник/водитель -> автомобиль
                   -> операция АЗС
                   -> путевой лист
                   -> месячная сверка ГСМ

## Справочник сотрудников

Номер топливной карты не хранится простым полем в work_employees. Используется
отдельная таблица work_employee_fuel_cards с периодами valid_from/valid_to.

Это позволяет менять карту сотруднику без переписывания старой истории.

Первая привязка может не иметь valid_from и тогда применяется к историческим
выпискам. При замене карты без явно указанной даты новая связь начинается с
текущей даты.

## Автомобили и водители

garage_vehicles содержит карточки автомобилей. Связь водитель -> автомобиль
также версионная и хранится в garage_driver_vehicle_assignments.

Поэтому операция АЗС за старый месяц относится к автомобилю, который был
назначен водителю в эту дату, а не обязательно к его текущей машине.

## Путевой лист

Базовый прозрачный расчёт:

    фактический расход =
        остаток на начало
        + получено/заправлено
        - остаток на конец

Если есть пробег и норма:

    нормативный расход = пробег * норма_л_на_100км / 100
    отклонение = фактический расход - нормативный расход

Модуль не подменяет ведомственные или законодательные правила определения
норм. Значение нормы задаётся в карточке автомобиля либо непосредственно в
путевом листе.

## Выписки ГСМ

В Documents Tooru добавлен тип fuel_statement — «Выписка ГСМ».

Логическая папка:

    Выписки ГСМ/YYYY/MM

Для старых .xls-выписок реализован встроенный OLE/BIFF reader без запуска
Microsoft Excel, макросов или формул. Он предназначен прежде всего для старых
табличных выгрузок топливных карт.

Из выписки извлекаются:

- период;
- номера топливных карт;
- подписи держателей, если есть;
- дата и время операции;
- АЗС;
- наименование топлива;
- цена;
- количество литров;
- сумма.

## Автоматическая привязка

Для каждой операции:

1. номер карты ищется в истории топливных карт;
2. находится сотрудник, владевший картой на дату операции;
3. по истории водитель -> автомобиль определяется машина;
4. операция получает статус linked.

Если карта неизвестна:

    card_unassigned

Если сотрудник найден, но автомобиль ещё не назначен:

    driver_no_vehicle

После создания недостающей связи ранее загруженные операции можно пересвязать
без повторного ввода данных.

## Месячная сверка

Garage Fuel Summary показывает:

- литры и сумму по выпискам;
- количество путевых листов;
- пробег;
- полученное топливо по путевым листам;
- фактический расход;
- нормативный расход;
- отклонение факт - норма;
- разницу «литры выписки - получено по путевым листам»;
- операции, которые ещё требуют привязки.

## Конфиденциальность

Реальные пользовательские выписки ГСМ не являются исходным кодом проекта и
не должны попадать в публичный GitHub. В репозитории допускаются только
обезличенные синтетические fixtures/tests.

## Диагностика

Состояние гаража и ГСМ включено в machine-readable report:

- garage status;
- garage stats;
- сотрудники/карты;
- автомобили;
- выписки;
- месячная сводка;
- непривязанные операции.
