# Автоматизация путевых листов — TooruDragon

## Каноническая модель

Путевой лист существует в системе один раз как сущность Waybill в
`garage_waybills`.

Карточка в Documents Tooru получает тот же ID. Гараж, ГСМ, Табель, память
проекта, граф связей и аналитика ссылаются на этот ID и не создают независимые
копии путевого листа.

## Пользовательский сценарий

1. Пользователь открывает Documents Tooru.
2. В блоке «Пачка путевых листов» выбирает PDF/JPG/PNG/TIFF.
3. Web UI отправляет файл частями, поэтому большой PDF не блокирует интерфейс.
4. Исходный файл сохраняется неизменяемым.
5. SHA-256 проверяется до создания новой пачки.
6. Создаётся durable P2 task.
7. Work Core обрабатывает пачку в фоне.
8. Пользователь видит стадии и счётчики.
9. После завершения показываются только Waybill, которые требуют проверки.
10. Возможная переработка показывается в Табеле отдельно и не является
    официальной до подтверждения человеком.

## Стадии

    uploaded
      -> splitting
      -> ocr
      -> extracting
      -> linking
      -> calculating
      -> validating
      -> completed

Пользовательские действия относятся к P0, открытый документ — P1, новые
загруженные документы и пачки путевых листов — P2, фоновая аналитика — P3,
переиндексация — P4. Реализованный worker обрабатывает waybill batch как P2.

## Оригинал

Оригинал пачки хранится отдельно:

    data/
      documents/
        Путевые листы/
          Оригиналы/
            <batch_id>/
              <исходное имя>

Файл не перезаписывается. Для пачки хранятся имя, SHA-256, размер, источник,
загрузивший пользователь, число страниц и состояние обработки.

## OCR один раз

OCR страницы хранится в `work_waybill_batch_pages`:

- page_number;
- engine;
- text;
- blocks + bounding boxes;
- tables;
- confidence;
- status/error.

При retry cached OCR используется повторно.

Backend order:

1. текстовый слой PDF через pypdf;
2. локальный pdftoppm + Tesseract;
3. Windows.Media.Ocr на Windows.

Ollama не используется.

Если локальный OCR недоступен для скана, задача завершается явной ошибкой.
Документ не отмечается «изученным» молча.

## Разделение пачки

Детерминированный splitter использует:

- заголовок «Путевой лист»;
- номер;
- дату;
- госномер;
- водителя;
- явный оборот/продолжение;
- последовательность страниц.

Явный оборот присоединяется к предыдущему Waybill. Неоднозначные продолжения
сохраняются, но получают needs_review.

## Извлекаемые поля

Для Waybill сохраняются структурированные значения и отдельный
`garage_waybill_fields` с:

- original_value;
- corrected_value;
- confidence;
- verified;
- provenance;
- corrected_at;
- corrected_by.

Поддерживаются номер/дата, организация, подразделение, автомобиль, госномер,
VIN, гаражный номер, водитель, табельный номер, выезд/возвращение, одометры,
остатки топлива, выдано/заправлено, топливо, маршрут, задание, примечания и
номер топливной карты.

## Привязка автомобиля

Госномер нормализуется:

- регистр;
- пробелы;
- дефисы;
- похожие кириллические/латинские символы.

Автоматическая привязка выполняется только при единственном точном
нормализованном совпадении или точном VIN. Новая машина автоматически не
создаётся.

## Привязка сотрудника

Приоритет:

1. точный табельный номер;
2. топливная карта на дату документа;
3. ФИО;
4. фамилия + инициалы;
5. существующая связь с автомобилем как дополнительное подтверждение.

При недостаточной уверенности employee_id остаётся NULL и Waybill требует
проверки.

## Папки

После анализа вычисляется:

    Путевые листы/
      YYYY/
        NN Месяц/
          <госномер марка модель>/
            <Фамилия И.О.>/
              YYYY-MM-DD_ПЛ_<номер>.pdf

Связь с общей пачкой не теряется. При наличии pypdf страницы исходного PDF
копируются в отдельный child PDF без повторного OCR. Если PDF backend
недоступен, ссылка на исходные страницы сохраняется и создаётся диагностическая
аномалия.

## Пробег

Для листа:

    distance = odometer_end - odometer_start

Для месячной сводки автомобиля:

    monthly_mileage =
        odometer_end последнего корректного Waybill
        - odometer_start первого корректного Waybill

Параллельно сохраняется сумма расстояний по листам и список разрывов между
концом предыдущего и началом следующего.

## ГСМ

Фактический расход:

    actual =
        fuel_open
        + fuel_issued
        + refueled
        - fuel_close

Норматив:

    norm_consumption = distance * norm_l_per_100km / 100

Отклонение:

    deviation = actual - norm_consumption

Математика выполняется Python/SQL, не LLM.

Waybill с needs_review не включается в официальную месячную ГСМ-сводку до
подтверждения.

## Выписка топливных карт

Используется существующий контур:

    сотрудник
      <-> топливная карта
      <-> автомобиль
      <-> Waybill
      <-> garage_fuel_transactions

Проверяются отсутствие соответствующего Waybill, расхождение литров,
неверный владелец карты, подозрительный объём и превышение указанной
вместимости бака.

## Возможная переработка

`work_overtime_candidates` не является официальным табелем.

Статусы:

- detected;
- needs_review;
- approved;
- rejected;
- applied_to_timesheet.

Для графика 08:00–17:00 и Waybill 07:15–19:40:

    before = 00:45
    after  = 02:40
    total  = 03:25

Переход через 00:00 поддерживается.

Нажатие «Подтвердить» является человеческим решением. Только после него
кандидат применяется к `work_timesheet_entries`.

Исправление кандидата не применяется сразу: после исправления статус снова
needs_review и требуется отдельное подтверждение.

## Память и граф

Непроверенный Waybill не записывается в память проекта как подтверждённый факт.

После уверенного анализа или подтверждения создаётся память со ссылкой
`source_document_id`.

Граф поддерживает, среди прочего:

    employee -> drove -> vehicle
    vehicle -> has_waybill -> waybill
    waybill -> on_date -> date
    employee -> uses_fuel_card -> fuel_card
    fuel_card -> has_refuel -> fuel_transaction
    fuel_transaction -> belongs_to_period -> YYYY-MM

Upsert не создаёт дубль одной и той же связи.

## Аудит

`work_audit_log` хранит:

- actor;
- action;
- entity;
- field;
- original_value;
- new_value;
- reason;
- source;
- source_document_id;
- timestamp.

Коррекция OCR не уничтожает исходное значение.

## Безопасная миграция

Старый `garage_waybills` перестраивается idempotent migration:

- старые строки сохраняются;
- employee_id/vehicle_id/trip_date становятся nullable для нераспознанных
  Waybill;
- старые расчётные поля не теряются;
- новые поля получают безопасные defaults;
- новые индексы создаются только после совместимой схемы.

## Производительность

Внешний AI не получает архив документов целиком. Основной контур использует
SQLite, правила, OCR и расчётный код. Внешний AI может использоваться позже
только для небольшого выбранного контекста сложного смыслового анализа.
